# 继承接口面（Inherited Cordis API）

官方原文：harness `docs/cordis-api/inherited.md`（生成文件；pinned vendor 源码，简明汇总版）。

每个插件在 harness 层之外都能看到的框架 `ctx` 成员与事件——vendor 的 cordis core + loader/hmr/timer。详细 API 见 [Context](Context.md)、[Fiber](Fiber.md)、[PluginRegistry](PluginRegistry.md)、[Service](Service.md)、[Events](Events.md)。

## 继承的 ctx 成员

- `ctx.on / ctx.once` —— 注册事件监听器（可释放）。
- `ctx.emit / ctx.parallel / ctx.serial / ctx.bail / ctx.waterfall` —— 分发事件（同步 / 等待 / 首个 bail / 短路链）。
- `ctx.plugin / ctx.inject` —— 加载插件 / 声明必需服务。
- `ctx.effect` —— 注册绑定到 fiber 的可释放副作用。
- `ctx.get / ctx.set / ctx.provide / ctx.accessor / ctx.mixin` —— 低层服务存储访问与绑定。
- `ctx.extend / ctx.isolate / ctx.intercept` —— 派生子上下文（作用域服务 / 隔离 / 拦截）。
- `ctx.root / ctx.scope / ctx.fiber / ctx.registry / ctx.reflect / ctx.events / ctx.logger` —— 运行中上下文图的环境句柄。
- `ctx.timer`（+ interval / timeout / throttle / debounce）—— 可释放定时器辅助；`timer` 键运行时提供，四个辅助直接混入 ctx。
- `ctx.loader` —— 启动应用的配置 Loader（在 loader 之下存在）。
- `ctx.hmr` —— 热重载 watcher（在 hmr 插件之下存在）。

## 继承的事件（cordis core + loader/hmr/timer）

- `internal/plugin` —— 创建了一个插件 fiber。
- `internal/status` —— fiber 生命周期状态变化（PENDING 诊断可监听此事件）。
- `internal/service` —— 服务绑定拦截钩子（无核心生产方）。
- `internal/update` —— **waterfall**：fiber 配置更新正在应用（更新钩子/HMR 可否决）。
- `internal/get` —— **waterfall**：正在从存储读服务。
- `internal/set` —— **waterfall**：正在向存储写服务。
- `internal/listener` —— 注册了一个监听器。
- `internal/dispatch` —— 事件正在分发给监听器。
- `hmr/change` —— 监视的源文件在磁盘上变化。
- `hmr/reload` —— 变化后插件正在重载。
- `exit` —— 进程收到信号退出。
- `loader/config-update` —— loader 配置树变化。
- `loader/entry-init` —— 配置条目正在初始化。
- `loader/partial-dispose` —— 重载中条目被部分释放。
- `loader/patch-context` —— 重载中上下文正在被 patch。

## 注意

这些是 vendor 层的接口面，harness 产品行为不依赖修改它们；插件开发日常用不到 `internal/*`，诊断（fiber 状态追踪、HMR 时机）时有用。

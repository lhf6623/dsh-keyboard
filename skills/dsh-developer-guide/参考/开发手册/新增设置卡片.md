# 新增设置卡片

官方来源：DSH 官方文档 Cookbook「新增设置卡片」（本页为官方 cookbook + harness 源码核实版；`ui-settings-plugins` 卡片、`settings.plugin.item` slot 已从源码验证）。

插件如何把自己的配置放上 Web 设置页。这条路径上没有任何一步需要改动 harness 仓库：**Host 服务每一个已注册的 settings 命名空间，而插件配置分区以卡片所编辑的命名空间为键，因此同时注册了两个半侧的插件会被自动配对。**

## 两个半侧住在同一个包里

- Host 半侧在 `src/`（注册 settings namespace）；
- 浏览器半侧在 `src/client/`（渲染设置卡片）；
- 以 `./client` 导出，并用 `dsh.client` 声明（`packages/client/ui-theme` 是这种打包方式的现成例子；插件配置分区自带的卡片在 `packages/client/ui-settings-plugins`）。

## 宿主半侧：注册 namespace

```ts
import {
  installSettingsSection,
  settingsNamespace,
} from "@deepseek-ai/dsh-settings";
import z from "@deepseek-ai/schemastery";

export const NS = settingsNamespace("dsh-vibe"); // 小写 kebab-case 校验

export interface Config {
  /* ... */
}
export const Config: z<Config> = z.object({/* 默认值写在 schema 里 */});

export default {
  inject: ["webServer"],
  apply(ctx: any, config: Config) {
    let source: () => Config = () => config;
    installSettingsSection(ctx, NS, Config, config, {
      setSource: (get) => {
        source = get;
      }, // 当前权威来源：settings 解析值或 entry 兜底
      onChange: () => {
        void source();
      }, // attach/detach/变更后重新判定派生状态
    });
  },
};
```

内部：`ctx.inject(['settings'], sctx => sctx.settings.register(ns, schema, { base: entry }))`——entry config 注册为 base 层，解析值 = schema 默认 < entry config < 用户层；settings 服务消失时自动回退 entry。宿主读「用户覆盖后的最终值」在 setSource 里拿。

## 浏览器半侧：绑定 namespace + 注册卡片

```ts
export const inject = [
  "slots",
  "settingsScope" /* + connection/remote 视需要 */,
];

export function apply(ctx: any) {
  // 1. 绑定自己编辑的命名空间（与 Host 注册的 namespace 同名 = 配对键）
  const scope = ctx.settingsScope.bind({
    namespace: "dsh-vibe",
    decode: (raw: unknown) => normalizeConfig(raw), // 宽容解码，旧值不打爆 UI
  });

  // 2. 把卡片注册进插件配置分区
  ctx.slots.inject("settings.plugin.item", () =>
    ctx.slots.register(
      { name: "settings.plugin.item", id: "dsh-vibe", order: 10 },
      PluginCard,
    ),
  );
}
```

`settings.plugin.item`（由 `ui-settings-plugins` 的 configurable tab 在运行时声明）：

- kind `list` / scope `root`；options：`id`（卡片 key）、`order`（卡片位置）。
- **卡片自绘全部内部结构**（文案/当前值/写路径都归注册方），分区只负责堆叠并报告数量。
- 分区的 `settings.plugins.tab` 是特性拥有的 tab；卡片之间、卡片与 tab 之间互不感知——都通过各自绑定的 settings scope 工作。

## settingsScope 读写

```ts
scope.getSnapshot();
// { status: 'loading' | 'ready' | 'unavailable', value, base, user, revision, writable, mode: 'host' | 'memory' }
scope.subscribe(listener); // 订阅变化
scope.set(field, value); // 写一个字段（异步，按 revision 冲突检测）
```

## 替代槽位（不放进插件配置分区时）

- `settings.section`（list/root）——独立设置页；options `id`（驱动 only 过滤）/`order`/`label`（本地化文本，可传函数）；组件收 owner prop `close: () => void`。
- `settings.general.item`（list/root）——通用设置里的一行；options `id`/`order`；**不投影 label**，整行自绘。

## 版本注意（以实测为准）

当前 harness checkout（0.1.0-rc.5）的 wire 层仍按暴露白名单过滤（`packages/host/apiproxy/src/api-proxy.ts`：`settings.describe` 过滤 `exposedNamespaces()` = 可配置模型提供方 + `WEB_SETTINGS_NAMESPACES` + `PRODUCT_SETTINGS_NAMESPACES`；白名单外浏览器读写会得 `settings-not-exposed`，源码注释称「把暴露声明移到 settings.register()」是 deferred work）。官方 cookbook 描述的是目标契约（注册即配对）；若卡片注册了但浏览器读不到值，先查你安装版本的暴露逻辑。纯 UI 偏好兜底走 localStorage 镜像（dsh-vibe 模式，见 [src/settings/config.ts](../../../src/settings/config.ts)）。

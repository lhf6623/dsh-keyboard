# 会话持久化事件目录

官方生成文件：harness `docs/persistence-catalog.zh.md`（英文源由 `scripts/gen-persistence-catalog.ts` 生成，`pnpm run verify-persistence-catalog` 验证新鲜度，doc-sync 门禁的一部分）。payload 完整声明以生成文件为准，不要手抄。

## 事件信封

```ts
// 每个事件的 type + 单调递增 seq + epoch 毫秒 time + data，
// 可选 ignorable（未知类型跳过标记），以及条件字段 surfaceOp / sourceEventSeqs
interface SessionEvent {
  type: string
  seq: number
  time: number
  data: /* SessionEventMap[type] */
  ignorable?: true
  surfaceOp?: 'append' | { op: 'replace'; start: number; end: number }   // 仅 surface 事件
  sourceEventSeqs?: number[]                                             // 仅 surface 事件
}
```

- **surface 事件** = `SurfaceEventType` 成员：`user/message`、`assistant/message`、`tool/result`——生成 LLM 消息，按 `surfaceOp` 加入 surface 列表（`append` 尾部追加；`replace` 从 start 到 end 整体替换，`sourceEventSeqs` 必须包含每个被遮蔽的节点，compaction 使用）。
- **log-only 事件** = 其余所有：可持久化、可回放，但不参与派生历史。
- 每个 payload 必须 JSON 可序列化（`Session.append` 处强制执行）；格式固定为 `SESSION_FORMAT_VERSION = 0`（预发布格式，不暗示兼容性）。
- `ignorable: true` 只标在纯信息记录上；读方遇到不认识的**必需**（无标记）事件类型必须拒绝重建会话，而不是静默丢弃——默认 required 意味着遗忘标记会过度拒绝，而非静默重建残缺会话。

## 与插件开发的关系

- 日志事件**不是** Cordis 事件——经唯一的 `session/event` emit 到达监听器（`(session, event)`，payload 在 `event.data`）；live-only，恢复/回放不重放。
- **新增模型可见输入 = 新增会话事件**：扩展 `SessionEventMap`（对 `@deepseek-ai/dsh-session/types` 声明合并）并从日志渲染；模型可见即已记录（运行时不变量）。
- 下游（仓库外）插件可以继续合并其他事件类型，这些类型按设计不属于本目录（注册表面是 deferred work）。
- 播放与恢复：`sessions.create(id, { seed })` 重放；`fromRestore` 的 seed 事件直入日志、不触发 `session/event`。

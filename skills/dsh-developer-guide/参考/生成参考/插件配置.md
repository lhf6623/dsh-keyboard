# 插件配置目录

官方生成文件：harness `docs/config-catalog.zh.md`（英文源由 `scripts/gen-config-catalog.ts` 生成，`pnpm run verify-config-catalog` 验证新鲜度，doc-sync 门禁的一部分）。**不要手抄目录内容**——以生成文件为准。

## 目录内容

每个 `config:` 块均可由 cordis.yml 条目设置。目录针对**每个可加载的 harness 包**，原样列出其 `apply` 函数或服务构造函数接收的配置声明（包括 JSDoc），并附上所有引用类型（包内类型直接粘贴，其他类型给链接）。

- **部署轴参考**：查「部署某个包时 cordis.yml 的 config 能写什么」就看这里。
- `Requires:` 行列出插件通过 `inject` 注入的服务键——cordis.yml 树还必须加载这些服务的提供方。
- 每条含来源链接（`packages/.../src/index.ts:70` 形式），JSDoc 即字段文档。

## 范围与边界

- 粘贴的内容是插件声明的**完整配置类型**；运行时 schema 有意排除的字段是仅供运行时使用的 seam（其 JSDoc 会说明），不能通过 cordis.yml 设置。
- 范围限定为 harness 层级（`packages/`）；vendored cordis 插件（`hmr`、console logger 等）固定为上游源码，未收录。
- 生成器会把运行时 schemastery schema 与粘贴声明交叉核对：每个经 schema 验证的键（含嵌套键）都必须能在声明类型中找到——粘贴内容无法隐藏 loader 接受的字段。

## 与插件作者的关系

- **部署者**（配置一个已发布插件）：查本目录 + `dsh --profile web --dump-config` 看实际生效的树。
- **插件作者**（写自己的插件）：连接方式见各子系统页面的生成 `cordis-surface` 区域；你自己的插件把 Config schema 写在插件模块里（见 开发/基础 的[插件配置](../../开发/基础/插件配置.md)），不在本目录范围内。

## 常用条目速查

dsh-vibe 相关的宿主行配置走自己的 Config schema（`enabled`/`feedback`/`flame`/`shake`/`response`/`pageShake`/`pageShakeLevel`/`sound`/`opacity`/`scale`，默认值在 [src/index.ts](../../../src/index.ts)）；web profile 常用条目的配置字段（agent-loop、bash、web-search 等）查目录里对应包名小节。

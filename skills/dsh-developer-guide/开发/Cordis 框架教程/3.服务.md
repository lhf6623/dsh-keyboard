# 3. 服务

官方原文：harness `docs/cordis-tutorial/03-services.zh.md`。

**服务**是一个插件提供、其他插件通过 `ctx` 消费的具名能力。在 harness 中 `ctx.tools`、`ctx.llm`、`ctx.agents` 都是服务。消费方只指定 `'tools'` 之类的能力名，不导入提供方——因此配置可以选择提供方，无需修改消费方。

## 提供服务

```ts
import { Service, type Context } from '@deepseek-ai/cordis'

declare module '@deepseek-ai/cordis' {
  interface Context { greeter: GreeterService }
}

export class GreeterService extends Service {
  constructor(ctx: Context) { super(ctx, 'greeter') }
  greet(who: string) { return `Hello, ${who}!` }
}

export const name = 'greeter'

export function apply(ctx: Context) {
  ctx.plugin(GreeterService)
}
```

两部分协同：

- **运行时**：`super(ctx, 'greeter')` 以名称 `greeter` 注册实例，任何插件此后可通过 `ctx.greeter` 访问。注册属于 effect，卸载提供方时移除服务。
- **编译时**：`declare module` 块用 TS 声明合并把 `greeter` 加进 `Context` 接口，使 `ctx.greeter` 各处通过类型检查。它不生成代码；没有该声明时服务运行时仍工作，但消费方失去类型安全。

`Service` 子类本身就是插件（类形态），所以 `ctx.plugin(GreeterService)` 像挂载其他插件一样挂载它。

## 用 inject 消费服务

```ts
export const name = 'consumer'
export const inject = ['greeter']

export function apply(ctx: Context) {
  console.log(ctx.greeter.greet('world'))   // ctx.greeter 已就绪
}
```

`inject` 列出插件需要的服务；Cordis 让插件保持 PENDING 直到每项服务就绪。**cordis.yml 里两行的顺序无关紧要**——决定启动时机的是依赖，不是文件顺序。移除 `./greeter.ts` 后消费方保持 PENDING、不输出、不崩溃、不部分运行；PENDING 的 fiber 不会让 Node 事件循环保持活跃，进程静默以状态码 0 退出。

## 加载后仍跟踪依赖

`inject` 不是一次性启动检查。应用运行期间所需服务消失（提供方卸载或热替换），每个依赖插件随之卸载，服务恢复后再次加载。结合 effect，这防止运行中的消费方保留对不可用服务的引用。这也是配置中可以替换服务的原因：换一个 `shell` 提供方，所有 `inject: ['shell']` 的插件自动重启使用新实现。

## 可选依赖

`inject` 用于硬性依赖。功能缺失仍可运行时就跳过 `inject`，在使用处探测：

```ts
export function apply(ctx: Context) {
  const greeter = ctx.get('greeter')   // 无提供方时 undefined，插件照常运行
  console.log(greeter?.greet('maybe') ?? 'no greeter available')
}
```

## 命名

每个应用中的服务名共用一个扁平命名空间。为自有服务加有辨识度的前缀或命名空间（harness 已占用 `tools`、`llm` 等普通名称）；harness 注册的每个名称见其子系统页面上生成的 `cordis-surface` 区块。

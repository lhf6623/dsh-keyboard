# 6. 组合与热重载

官方原文：harness `docs/cordis-tutorial/06-composition-and-hmr.zh.md`（官方用词「HMR」）。

到目前为止构建的每项能力都是插件，`cordis.yml` 则选择应用的插件树。本章改变组合、热重载一个插件，并诊断始终无法加载的插件。

## Cordis 配置项不只有名称

```yaml
- id: greeter # 稳定标识：让 loader 能区分「修改现有项」与「删除再添加」
  name: "./greeter.ts"
- id: consumer
  name: "./consumer.ts"
  disabled: true # 保留该项但跳过挂载；改回后插件及其 PENDING 依赖者再次加载
```

组可以嵌套一份配置项子列表，并作为一个单元加载/卸载；`isolate` 为一个组提供某项服务名称的独立实例（两个组各自看到配置不同的 `shell` 提供方，互不影响）。

## 热重载（HMR）

卸载释放 effect、加载遵循依赖，所以 HMR 可以先卸载、再加载，替换运行中的插件。`@deepseek-ai/cordis-plugin-hmr` 监视文件并在保存时执行这一过程：

```yaml
- id: logger
  name: "@deepseek-ai/cordis-plugin-logger-console"
- id: timer
  name: "@deepseek-ai/cordis-plugin-timer"
- id: hmr
  name: "@deepseek-ai/cordis-plugin-hmr"
  config:
    root: ["."]
- id: hello
  name: "./hello.ts"
```

两个辅助插件缺一不可：HMR 通过 Cordis logger 服务记录日志（没有 console 导出器时看不到消息），并 `inject` `timer` 服务实现去抖（没有 timer 时永远停在 PENDING 且无提示）。

编辑 `hello.ts` 保存：旧实例先卸载（effect 全部回卷），新代码加载、`apply` 再次运行。编辑 `cordis.yml` 本身也触发更新：loader 按 `id` 比较配置项，只挂载/卸载/重新配置变化的部分——**不带 `id` 的项每次读取都获得新生成 id**，所以任何配置编辑都会把它当「删除再添加」重新挂载，即使自身文本未变。

## 诊断始终无法加载的插件

依赖驱动加载的另一面：`inject` 指定了无人提供的服务，插件就一直等待、不输出任何内容。这不是错误——PENDING 是合法状态，提供方可能稍后才挂载。

直接查看状态：

```ts
import { FiberState, type Context } from "@deepseek-ai/cordis";

export const name = "diagnose";

export function apply(ctx: Context) {
  setTimeout(() => {
    for (const runtime of ctx.registry.values()) {
      for (const fiber of runtime.fibers) {
        if (fiber.state === FiberState.PENDING) {
          console.log(
            `${fiber.name} is PENDING — a required service is missing`,
          );
        }
      }
    }
  }, 500);
}
```

如果插件既不执行任何操作也不报告任何内容，先查 fiber 状态。不加 PENDING 过滤迭代时，还会看到 loader 自身的插件（Loader、Include）处于 ACTIVE——配置文件本身也是通过插件挂载的。

# 第一个插件

官方原文：harness `docs/user/develop/basic/index.zh.md`。

## 插件是什么

在 Harness 中，插件是一个导出 `apply` 函数的 TypeScript 模块。框架在加载时调用 `apply`，传入一个 `ctx`（上下文对象），你通过 `ctx` 注册能力：

```ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'my-plugin'

export function apply(ctx: Context) {
  // Register capabilities here.
}
```

`name` 是可选显示元数据，用于诊断信息中标识插件。

## 声明依赖

需要使用其他服务（`tools`、`llm`、`webServer`…）时声明 `inject`。框架保证这些服务就绪后才调用 `apply`：

```ts
export const name = 'my-tool-plugin'
export const inject = ['tools']

export function apply(ctx: Context) {
  // ctx.tools is ready here.
}
```

硬依赖才写进 `inject`；缺失也能运行的功能用 `ctx.get('xxx')` 在使用处探测（可选依赖）。

## 自动清理

通过 `ctx` 做的任何注册（事件监听、工具、定时器）在插件卸载时自动撤销，不需要手动 removeListener / clearInterval。Cordis 不管理的资源（网络连接等）用 `ctx.effect()` 告诉框架怎么清理：

```ts
export function apply(ctx: Context) {
  ctx.effect(() => {
    const timer = setInterval(() => console.log('heartbeat'), 5000)
    return () => clearInterval(timer)   // 插件卸载时运行
  })
}
```

## 插件的三种形态

```ts
// 1. 函数（大多数情况够用）
export function apply(ctx: Context) {}

// 2. 对象（inject + apply 写在对象里；dsh-vibe 宿主用的形态）
export default { inject: ['tools'], apply(ctx: Context) {} }

// 3. 类（需要向其他插件提供服务时；见 参考 的 Cordis 服务章节）
export default class MyService extends Service {
  static inject = ['tools']
  constructor(ctx: Context) { super(ctx, 'myService') }
}
```

## 本地加载两种方式

**官方 scratch 方式**（临时验证，不改任何包）：在 harness 仓库里建 `scratch-plugin/`，用 `--patch` overlay 插入本地行：

```yaml
# scratch-plugin/cordis.yml（插件路径必须绝对路径）
- insert:
    - id: hello
      name: '/absolute/path/to/scratch-plugin/src/my-plugin.ts'
```

```sh
pnpm dsh web --patch ./scratch-plugin/cordis.yml   # 仓库内；已安装 CLI 则 dsh web --patch …
```

**bundle 插件方式**（dsh-vibe 的日常）：改 src/ → `npm run watch` 重建 lib/ → 客户端半边由 harness 内置的 dsh-client-hmr 热替换（stat-poll mtime → SSE rebuilt → 浏览器重新加载），宿主半边无热替换、需重启 harness。详见 [打包与安装插件](打包与安装插件.md)。

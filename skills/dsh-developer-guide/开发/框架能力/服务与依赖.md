# 服务与依赖

官方原文：harness `docs/user/develop/framework/service.zh.md`；动手版：`docs/cordis-tutorial/03-services.zh.md`。

## 什么是服务

服务是一个插件提供、其他插件通过 `ctx` 消费的**具名能力**。在 Harness 中 `tools`、`llm`、`agents` 都是服务；消费方只指定能力名，不 import 提供方——因此配置可以替换提供方而无需修改消费方。

## 使用服务：inject

```ts
export const inject = ['tools']

export function apply(ctx: Context) {
  // ctx.tools 已就绪
  ctx.tools.register(/* ... */)
}
```

- **硬依赖**：写进 `inject`，服务不在则插件保持 PENDING。
- **可选依赖**：不写 `inject`，使用处探测——`const metrics = ctx.get('metrics'); metrics?.record(...)`（无提供方时为 undefined，插件照常运行）。

## 提供服务：Service 基类

```ts
import { Service, type Context } from '@deepseek-ai/cordis'

declare module '@deepseek-ai/cordis' {
  interface Context { metrics: MetricsService }
}

export default class MetricsService extends Service {
  static inject = ['llm']            // 服务自身也可以依赖其他服务

  constructor(ctx: Context) {
    super(ctx, 'metrics')            // 'metrics' 即服务名
  }

  record(event: string, value: number) { /* ... */ }
}
```

- `super(ctx, 'metrics')` 在运行时注册实例，此后任何插件都可通过 `ctx.metrics` 访问；注册属于 effect，卸载提供方时移除服务。
- `declare module` 块用 TS 声明合并把 `metrics` 加进 `Context` 接口（编译时类型，不生成代码）。

## 命名

服务名在应用内是**扁平命名空间**。为自有服务加辨识前缀（harness 已占用 `tools`/`llm` 等普通名）。harness 内置服务清单见 参考（capability seams 的 ctx 键一栏表），以生成的子系统页面为准，不要维护静态清单。

## 服务隔离

`cordis.yml` 支持同一个服务多实例——不同插件组看到不同实例：

```yaml
- id: group-a
  name: '@deepseek-ai/cordis-plugin-group'
  group: true
  isolate:
    shell: true
  config:
    - name: '@deepseek-ai/dsh-bash-local'
      config: { timeoutMs: 5000 }
    - name: './src/plugin-a.ts'
```

`plugin-a` 与另一组里的插件各自看到组内自己的 shell 实例，互不影响。

## 三层能力设计

可替换能力（如 shell、fs、compaction）按**Service Definition / Service Provider / Consumer** 三角色组织：接口包定义 `ctx.<key>` 与词汇类型（抽象类或具体注册表，绝不是 TS interface），提供方包给出实现，消费方包注入服务。角色独立演进时拆包（`dsh-shell` + `dsh-bash-local` + `dsh-tool-bash` 是规范范例）；详见 harness `docs/user/develop/practice/index.zh.md` 与 `docs/capability-seams.zh.md`。
